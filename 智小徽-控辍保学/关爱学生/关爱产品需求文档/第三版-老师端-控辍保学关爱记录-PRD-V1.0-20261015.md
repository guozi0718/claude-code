## 1. 需求背景

本方案复制第一版老师端完整框架，去掉老师端首页独立“关爱”入口，在“控辍保学”页面增加与“预警记录”“劝返记录”并列的第三个Tab“关爱记录”。关爱改为逐次记录：每完成一次关爱，就保存一条独立记录。老师每次重新选择学生并填写关爱背景和实际措施；同一学生可以有多条独立记录，每条只有一份关爱内容，不在记录中追加下一次内容。学校和监管查看这些记录，监管按组织统计参与关爱的学生人数及关爱次数。第一期其他方案不覆盖、不迁移、不删除。

## 3. 文档说明

### 3.1 名词解释

| 项目 | 当前版本规则 |
|---|---|
| 关爱记录 | 一次提交形成的一条完整记录，绑定一名学生。包含学生信息、八项关爱业务字段和系统信息，不再设置上层关爱个案。 |
| 关爱类型 | 学生所处情况或问题分类，12项多选。分类不是诊断结论，也不自动判定资助或医疗资格。 |
| 关爱方式 | 这一次实际采取的措施，15项单选。多人执行仍是一次，不按执行人数增加次数。 |
| 执行人员与创建人 | 执行人员是实际参与老师，可多人；创建人是第一次提交成功的账号姓名，由系统填写，两者不能相互替代。 |
| 关爱时间与创建时间 | 关爱时间是实际发生日期，可补录；创建时间是首次创建的服务端时间，保存到秒、以北京时间显示到分钟；修改时间单独留审计。 |
| 关爱次数 | 当前查询范围内未删除的独立记录数量。只在监管组织汇总显示，不在学生底层记录列表增加次数列。 |
| 关爱学生数 | 当前查询范围内至少有一条有效记录的学生ID去重数，不能用姓名去重，也不能把各分类人数简单相加。 |

### 3.2 编写要求

本文为本端完整独立说明，不用其他PRD补全字段。所有校验和提示写在所属字段、页面或动作内；没有独立校验汇总章。最新模板完整读取自GitHub main，模板文件blob为 8fecf490895c595ca9219058a4b4ec8d7ca80c7b，模板来源提交 36ac07c8e721808726e286311c76bca31201085b。用词按业务操作说明，不把模板示例当新增业务要求。

当前原型是会话模拟：记录、图片和审计只存在本页内存，刷新恢复示例，不跨标签页或跨端同步。真实系统须在服务端做范围与权限校验、版本校验、提交去重、记录保存和审计落库，不能凭前端隐藏按钮保证权限。接口地址、错误码和事务方案【待确认】。

## 6. 功能详细说明

### 6.1 关爱记录列表

[本页原型](https://guozi0718.github.io/codex/关爱学生/关爱三端原型/第三版-老师端关爱管理-V1.0-20261015.html#care-v3)

#### 6.1.1 页面说明

| 项目 | 当前版本规则 |
|---|---|
| 入口与返回 | 老师端首页不再出现独立“关爱”入口。从“控辍保学”进入后，顶部依次为“预警记录、劝返记录、关爱记录”。控辍保学左上角返回原老师端首页；新增、编辑、详情返回“关爱记录”Tab，并保留姓名搜索、已加载批次数量和滚动位置。返回目标来自页面进入来源白名单，不能由任意URL参数跳转。 |
| 默认 | 默认展示当前学年内、账号有权查看学生范围中的有效关爱记录；无状态Tab，姓名搜索为空。当前学年按关爱时间归属：每年9月1日至次年8月31日。按后端记录的首次创建日期时间倒序，后端保存到秒，同秒再按记录ID倒序稳定排列；列表显示到分钟。不是按关爱时间或最后修改时间排序。编辑任何业务字段都不重置首次创建时间，也不改变其排序依据。不显示“第几次关爱”，不将同一学生的记录合成一个个案。 |
| 权限开关 | 查看范围与记录操作权限分别受权限管理：先按学生数据范围决定能看哪些记录；本人提交的记录还需同时具有关爱写权限和记录操作权限才能编辑、删除。新建需要关爱写权限开启且学生在范围内。原型顶部切换王老师（查看全部且可操作本人记录）、李老师（仅班主任范围且可操作本人记录）、陈老师（可查看但无写入和操作权限）。正式范围由账号授权决定，不由URL参数决定。 |
| 更新 | 首次进入、搜索、从详情返回以及新增/编辑/删除成功后重新计算。新建不继承上次学生或关爱背景。 |
| 空与失败 | 查询成功无记录显示“暂无符合条件的关爱记录”，总条数为0；部分字段缺失显示“--”，不能把读取失败当成没有记录。正式接口若仅返回部分页，保留已加载数据并按接口总数翻页，不用已加载条数假装总数；接口失败保留上一次成功列表和查询条件，允许重新查询，具体错误码、超时、重试文案【待确认】。原型一次加载会话示例数据，不模拟真实接口。 |

| 条件 | 控件 | 必填 | 默认值 | 数据来源与枚举 | 规则、提示与异常 |
|---|---|---|---|---|---|
| 学生姓名 | 搜索输入框＋候选回显 | 否 | 空，占位“搜索学生姓名” | 当前学年且授权范围内学生姓名 | 输入即按姓名包含模糊匹配，忽略两端空格，并回显匹配姓名候选；点候选后按该姓名查询。清空恢复当前学年全部可见记录。搜索不能扩大权限范围。同名学生均返回，以年级班级区分。输入长度上限和正式服务端防抖【待确认】。 |

| 字段 / 区域 | 数据来源 | 显示格式 | 规则、交互、提示与异常 |
|---|---|---|---|
| 总数 | 当前搜索有效记录 | 共N条关爱记录 | 按记录条数，不按去重学生或执行老师数。未加载成功不能冒充0。 |
| 学生卡头 | 学生快照 | 姓名、年级、班级 | 同生可出现多个卡片；不自动归并。 |
| 卡片字段 | 当前一条记录 | 来源→类型→原因→关爱时间→关爱结果 | 保存值全文换行；详情可看执行人、方式、材料和系统信息。长文本不得越出手机框；不再放关联信息、次数、最近日期、状态。 |
| 详情 | 记录ID | 卡片右下按钮 | 进入这一条记录详情。原型卡片本体不作隐式编辑入口。 |
| 新增关爱记录 | 关爱写权限 | 页面底部主按钮 | 有权限打开全新表单，无写权限置灰，不显示额外劝说提示。绕过直接入口或提交仍拒绝，反馈“暂无权限”。 |
| 列表滚动与懒加载 | 本次查询记录 | 手机内纵向滚动，每批20条 | 首次只加载前20条；滚动接近底部再加载下一批20条，直到全部加载完成。搜索条件变化时从首批20条重新加载。加载中防止重复请求；失败保留已加载内容并允许再次滚动重试，正式失败文案【待确认】。表头、Tab和底部新增按钮不跳出手机。 |

### 6.2 新增 / 编辑关爱记录

[本页原型](https://guozi0718.github.io/codex/关爱学生/关爱三端原型/第三版-老师端关爱管理-V1.0-20261015.html#care-v3)

#### 6.2.1 页面说明

| 项目 | 当前版本规则 |
|---|---|

| 新增默认 | 学生三项空、来源和类型空、原因空、方式空、结果空、材料空；关爱时间为北京时间当天。执行人员在选择学生后默认其班主任。 |
| 编辑回显 | 完整回显本人该条记录的所有业务字段和材料；学生信息也可修改。没有追加字段，没有系统创建人/创建时间输入框。 |
| 字段顺序 | 学生信息：年级→班级→学生姓名。关爱内容：关爱来源→关爱类型→关爱原因→关爱时间→执行人员→关爱方式→关爱结果→证明材料。来源多选、类型多选、方式单选。 |
| 入口与提交权限 | 进入与保存都核验功能权限、学生范围、本人归属；修改目标学生也必须在授权范围。对象不属于本人或无写权限提示“暂无权限”，不落库。原型直接#new、#edit/ID同样校验。 |

| 分工 | 前端做即时提示与防误触；服务端复核身份、学生归属、枚举、日期、字数、材料和版本。身份与系统时间不可采信客户端。 |

#### 6.2.2 表单字段（按页面顺序）

| 字段 | 控件 | 必填 | 默认 / 回显 | 数据来源与枚举 | 规则、提示与异常 |
|---|---|---|---|---|---|
| 年级 | 单选底部选择器 | 是 | 新建空；编辑原年级 | 当前授权学校/学生范围可选年级 | 占位“请选择年级”。选择后点确定生效；换年级清空班级、学生和执行人员，即使原班级名在新年级同名也清空。空提交“请选择年级”，保留其他输入。 |
| 班级 | 单选底部选择器 | 是 | 空或已保存班级 | 已选年级下授权班级 | 占位“请选择班级”；未选年级禁用。换班级清空学生和执行人员。空提交“请选择班级”。取消选择不改原值。 |
| 学生姓名 | 单选底部选择器 | 是 | 空或已保存学生 | 已选年级与班级下、当前账号数据范围内的在读学生，关联键为学生ID | 占位“请选择学生姓名”；未选班级禁用。选择时记录学生ID、在读状态版本及当前年级班级，选择后默认执行人员为该生班主任。提交时服务端再次复核：学生已变为非在读，阻止保存并提示“该学生当前不是在读状态，不能新增关爱记录，请重新选择学生。”；年级或班级变化，阻止本次保存、刷新最新值并提示“该学生的年级或班级已发生变化，已更新为“{最新年级}·{最新班级}”，请确认后重新提交。”；学生已转出或超出数据范围提示“该学生已不在您的数据范围内，请重新选择学生。”，不得泄露转入学校；学生失效提示“学生信息已更新，请重新选择学生。”。所有失败保留已填写的关爱内容。选择时的年级班级作为新记录历史快照，学生以后升年级、调班、毕业或转学均不回写旧记录。 |
| 关爱来源 | 多选底部选择器 | 是 | 新建空；编辑已选 | 完整选项：辍学预警、心理测评、班主任发现、任课教师反映、学生主动反映、家长反映、困难学生、欺凌事件、其他 | 占位“请选择关爱来源”；至少1项，最多全部9项。按选项顺序回显，多项顿号连接，窄屏单行省略，打开选择器核对全项。空或无效值提交“请选择关爱来源”。本版不再随来源展示关联选择，不强制锁定控辍保学。 |
| 关爱类型 | 多选底部选择器 | 是 | 新建空；编辑已选 | 完整字典：CARE_TYPE_01＝家庭经济困难学生；CARE_TYPE_02＝农村留守儿童；CARE_TYPE_03＝进城务工随迁子女；CARE_TYPE_04＝单亲 / 监护缺失学生；CARE_TYPE_05＝随班就读残疾学生；CARE_TYPE_06＝心理行为偏差 / 情绪困扰学生；CARE_TYPE_07＝心理危机学生；CARE_TYPE_08＝慢性疾病需特殊照料学生；CARE_TYPE_09＝学业困难学生；CARE_TYPE_10＝升学考试焦虑学生；CARE_TYPE_11＝遭遇校园欺凌霸凌学生；CARE_TYPE_12＝家庭突发变故学生 | 至少1项、最多12项；按固定字典顺序排列；多选不会拆分记录或增加次数。空或非法枚举“请选择关爱类型”。回显截断不改变保存全文。 |
| 关爱原因 | 多行文本 | 是 | 空或原文 | 老师描述本次关爱背景 | 占位精确为“请填写学生的真实情况”。字段标题右侧实时显示“已输入字数/100”，初始0/100；输入maxlength=100，达到100字后不可继续输入。去掉两端空白后至少1字；纯空白提示“请填写关爱原因”，服务端超100提示“关爱原因最多100字”，保留当前内容并定位此字段。当前计数沿用JS字符串长度，特殊表情正式计数口径【待确认】，不得前后端采用互相冲突的计数。 |
