## 1. 需求背景

老师端首页不设独立“关爱”入口，在“控辍保学”页面中与“预警记录”“劝返记录”并列设置第三个Tab“关爱记录”；预警记录、劝返记录中不包含关爱内容。关爱采用逐次记录：每完成一次关爱，就保存一条独立记录。老师每次重新选择学生并填写关爱背景和实际措施；同一学生可以有多条独立记录，每条只有一份关爱内容，不在记录中追加下一次内容。学校和监管查看这些记录，监管按组织统计参与关爱的学生人数及关爱次数。

## 3. 文档说明

### 3.1 名词解释

| 项目 | 当前版本规则 |
|---|---|
| 关爱记录 | 一次提交形成的一条完整记录，绑定一名学生。包含学生信息、八项关爱业务字段和系统信息，不设置上层关爱个案。 |
| 关爱类型 | 学生所处情况或问题分类，12项多选。分类不是诊断结论，也不自动判定资助或医疗资格。 |
| 关爱方式 | 这一次实际采取的措施，15项多选（至少1项）。多人执行仍是一次，不按执行人数增加次数。 |
| 执行人员与创建人 | 执行人员是实际参与关爱的人员，由老师手动填写，可多人；创建人是第一次提交成功的账号姓名，由系统填写，两者不能相互替代。 |
| 关爱时间与创建时间 | 关爱时间是实际发生日期，可补录；创建时间是首次创建的服务端时间，保存到秒、以北京时间显示到分钟；修改时间单独留审计。 |
| 关爱次数 | 当前查询范围内未删除的独立记录数量。只在监管组织汇总显示，不在学生底层记录列表增加次数列。 |
| 关爱学生数 | 当前查询范围内至少有一条有效记录的学生ID去重数，不能用姓名去重，也不能把各分类人数简单相加。 |

### 3.2 原型说明

当前原型是会话模拟：记录、图片和审计只存在本页内存，刷新恢复示例，不跨标签页或跨端同步。真实系统须在服务端做范围与权限校验、版本校验、提交去重、记录保存和审计落库，不能凭前端隐藏按钮保证权限。接口地址、错误码和事务方案【待确认】。

### 6.2 新增 / 编辑关爱记录

[本页原型](https://guozi0718.github.io/claude-code/智小徽-控辍保学/关爱学生/关爱三端原型/第三版-老师端关爱管理-V1.4-20261015.html?page=teacher-care-new)

#### 6.2.1 页面说明

| 项目 | 当前版本规则 |
|---|---|
| 页面标题 | 新建为“新增关爱记录”，编辑为“编辑关爱记录”。 |
| 新增默认 | 学生三项空、来源和类型空、原因空、方式空、结果空、材料空；关爱时间为北京时间当天。执行人员为空；选择学生后若执行人员仍为空，自动填入该生班主任姓名，可修改。 |
| 编辑回显 | 完整回显本人该条记录的所有业务字段和材料。学生信息（年级、班级、学生姓名）只读展示创建时的快照，不可修改，不显示下拉箭头；如记错学生，需删除后重新新增。没有追加字段，没有系统创建人/创建时间输入框。 |
| 字段顺序 | 学生信息：年级→班级→学生姓名。关爱内容：关爱来源→关爱类型→关爱原因→关爱时间→执行人员→关爱方式→关爱结果→证明材料。来源多选、类型多选、方式多选。 |
| 入口与提交权限 | 进入与保存都核验功能权限、学生范围、本人归属。编辑对象不属于本人或无记录操作权限提示“暂无权限”，无新增权限提示“账号权限变更，请联系管理员”，均不落库。 |
| 离开 | 点左上角“‹”时先判断内容有无修改：新增与进入时的空白表单相比、编辑与打开时回显的内容相比，各字段及证明材料均未变化时直接返回列表，不弹窗；有任一修改时弹出“放弃填写”居中对话框，正文“当前内容尚未保存，确认离开？”，取消留在原表单，确定放弃本次填写并回列表（编辑放弃不改变原记录）。刷新或关闭页面由浏览器未保存提示处理。 |
| 页面框架 | 分“学生信息”“关爱内容”两张白色圆角卡片；每个选择字段为一行，左侧标签＋红色*，右侧显示已选值（深色）或灰色占位＋下拉箭头；前置条件未满足时（未选年级的班级、未选班级的学生姓名）整行置灰不可点；执行人员为单行输入框，右对齐输入。关爱原因/结果为多行文本框，标题右侧显示“N/100”；证明材料为“＋”上传格与缩略图，标题右侧显示“N/9”，读取中显示“图片读取中…”。底部固定蓝色“确定”。 |
| 校验展示 | 点“确定”后分两步：第一步前端按字段顺序校验，第一处不通过的提示以红色小字显示在该字段下方并自动滚动定位，不发起提交；第二步按钮变为“提交中…”并置灰（防止重复提交），服务端按“网络→记录是否存在→账号权限→学生（失效→在读→数据范围→年级班级）→记录版本”顺序复核，第一处不通过即停止并提示。学生类提示显示在“学生姓名”字段下方；权限、版本、网络类提示以toast展示并同时显示在表单底部；记录已不存在时toast后返回列表。重新选择或输入该字段时清除提示。所有失败均保留已填写的关爱内容。 |
| 分工 | 前端做即时提示与防误触；服务端复核身份、学生归属、枚举、日期、字数、材料和版本。身份与系统时间不可采信客户端。 |

| 对象不存在 | 从列表打开或通过链接打开时，记录被删除、已不在范围或链接失效，提示“记录已变化，请刷新后重试”并返回关爱记录列表，不展示其他学生数据，也不显示上一次记录的内容。详情读取网络失败提示“网络异常，请稍后重试”并返回列表。 |
| 缺失、加载与图片失败 | 已加载字段正常展示，缺失“--”；图片失败显示“图片加载失败”，悬停“图片加载失败，请重新打开”，不隐藏整条内容。正式读取失败保留列表并允许重开，接口文案【待确认】。 |

### 6.4 权限规则

#### 6.4.1 权限构成

| 权限项 | 控制方式 | 规则 |
|---|---|---|
| 功能权限 | 后台按职务配置 | 职务决定账号是否有关爱记录查看、新增、记录操作（编辑、删除）权限。权限调整后即时生效，进入页面、点击操作和提交时服务端均复核。 |
| 数据范围 | 班主任所带班级＋任课老师所任教班级 | 账号可见学生为其担任班主任的班级与任课班级学生的并集。本期不区分班主任和任课老师的权限及范围，两者可查看、新增的规则相同。 |
| 编辑、删除记录 | 提交人本人 | 仅记录的提交人（创建人）可编辑、删除自己提交的记录，且须同时满足：职务有新增和记录操作权限、学生在当前数据范围内。执行人员中包含自己不等于提交人。 |
| 他人提交的记录 | 职务权限＋数据范围 | 范围内可查看列表和详情，不显示“...”，不能编辑、删除。 |
| 学校端 | 职务权限＋本校范围 | 查看本校记录；具备删除权限的可删除本校任意老师提交的记录，老师端同步不再显示。不提供新增、编辑。 |
| 监管端 | 职务权限＋组织范围 | 只读查看，不提供新增、编辑、删除。 |

#### 6.4.2 人员或职务变动后的历史记录

| 场景 | 原提交人 | 接手老师 | 说明 |
|---|---|---|---|
| 更换班主任，原班主任仍任该班课程 | 学生仍在其数据范围内，可继续编辑、删除自己提交的记录 | 可查看该班历史记录；不能编辑、删除原班主任提交的记录；可新增，并编辑、删除自己新增的记录 | 记录的提交人、创建时间不变。 |
| 更换班主任，原班主任不再任教该班 | 学生不在其数据范围内，看不到也不能编辑、删除这些记录 | 同上 | 历史记录完整保留，不随人员变动删除或转给他人；本期不提供记录移交。 |
| 任课老师调整 | 同“原班主任不再任教该班”：不在范围即不可见、不可改 | 新任课老师可查看范围内历史记录，只能编辑、删除自己提交的记录 | 与班主任规则一致。 |
| 原提交人职务权限被收回 | 不显示“...”，不能编辑、删除；有查看权限时仍可查看 | — | 提示文案见6.1.2、6.2.4。 |
| 原提交人账号停用或离职 | 无法登录，不能编辑、删除 | 范围内老师可查看，不能修改 | 记录保留，创建人显示原姓名。 |
